1. Executive Summary & Current Architecture Baseline

Learning.AI is an advanced, full-featured online education and AI-proctored examination platform designed for personalized learning, adaptive testing, and integrity-verified student assessments. The platform incorporates machine learning principles to dynamically calibrate test difficulty, monitor student biometrics and webcam feeds in real time, and map learning journeys across software engineering disciplines.

Architectural Assessment Summary: The core logic, schemas, and user journeys are exceptionally feature-rich. However, transitioning from a monolithic development model to a distributed Vercel serverless deployment has exposed several architectural friction points—namely, stateful media uploads, unseeded collections, and database connection lifecycle orchestration. With the architectural refinements outlined below, Learning.AI will operate as an enterprise-grade, highly resilient platform.

2. Platform Domain & Feature Directory

2.1 Adaptive Testing & Dynamic MCQ Engine

The adaptive exam system is the intellectual core of the assessment tier. Rather than presenting fixed linear questionnaires, the engine assesses student responses in real time and dynamically adjusts subsequent question difficulty:

  • Difficulty Calibration Engine (AdaptiveDifficultyEngine.js): Continuously updates the student's estimated ability level based on question difficulty parameters and consecutive hit/miss patterns.
  • Adaptive Exam Session Controller (AdaptiveExamSession.jsx, adaptiveExamController.js): Manages test state, time limits, question pagination, answer submission, and score calculation.
  • Dynamic MCQ Routing (AdaptiveRoutingConfig.jsx, AdaptiveWaitScreen.jsx): Provides smooth transitions between question pools without full-page reloads, retaining test integrity in intermittent connectivity.

2.2 AI Biometric Proctoring & Camera Surveillance

To ensure credential and exam integrity, Learning.AI implements a comprehensive proctoring subsystem:

  • Biometric Identity Capture (BiometricCapture.jsx): Captures facial snapshots during onboarding and exam entry, matching them against baseline student records.
  • Real-Time Camera Proctoring (CameraMonitor.jsx, cameraRoutes.js): Monitors candidate webcam video feeds throughout active testing sessions, periodically dispatching video chunks.
  • Admin Biometric Verification Console (AdminBiometricApproval.jsx, BiometricApproval.jsx): Allows proctors and exam administrators to approve, reject, or flag candidate biometric captures before exams commence.

2.3 Interactive Curriculum, Skill Roadmaps & Gamification

Learning.AI guides learners through standardized curriculum trees:

  • Domain Roadmaps (Roadmap.jsx, LearnPaths.jsx): Predefined tracks for Full-Stack Development, Frontend, Backend, AI/ML, Mobile, DevOps, and Data Science.
  • Lesson Explorer (LessonDetail.jsx, ContentViewer.jsx): Deep-dive theoretical and practical content for individual syllabus topics.
  • XP & Gamification Engine (xp.service.js, xp.routes.js): Calculates experience points, study streaks, and mastery tier badges to sustain student engagement.

2.4 Custom Learning & Personalized Question Engine

  • Personalized Question Sets (PersonalizedQuestionSetService.js): Generates targeted practice exams focused specifically on a learner's identified weak points across previous assessments.
  • Custom Quiz Builder (CustomLearning.jsx, CustomQuizHistory.jsx): Gives students the flexibility to practice specific domains at chosen difficulty levels.

2.5 Admin Operations, Exam Creation & Live Monitoring

  • Visual Exam Authoring Studio (AdminExamCreate.jsx, AdminExamManage.jsx): Comprehensive tool for creating exams, setting pass thresholds, specifying duration, importing questions via CSV, and defining proctoring policies.
  • Live Monitoring Room (ExamMonitor.jsx, ExamDashboard.jsx): Real-time overview of active candidates, connection statuses, warnings, and biometric discrepancies.
  • Performance Analytics Dashboard (AnalyticsDashboard.jsx, ExamAnalytics.jsx): Visual analytics highlighting cohort pass rates, question discrimination indices, and time-per-question distributions.

2.6 Authentication, Multi-Provider Identity & Security

  • Local Authentication: Salted SHA-256 password hashing with a server-side cryptographic pepper and 6-digit email OTP verification.
  • Google OAuth 2.0: Streamlined one-click sign-in leveraging Google accounts, auto-provisioning linked Learner and User records.
  • Token Management: Short-lived JWT access tokens accompanied by cryptographically signed refresh tokens with automated rotation.

3. Senior Architectural Evaluation & Gap Analysis

Area Severity Current Implementation Detail Architectural Remedy
Video Proctoring Storage Critical recordingService.js writes video chunks to local disk via fs.appendFile into app/Backend/uploads/recordings. Fails on Vercel's read-only ephemeral filesystem. Migrate to direct-to-cloud upload using Presigned S3/Cloudflare R2 URLs. Frontend streams chunks directly to cloud object storage.
Database Seeding High Empty collections in MongoDB Atlas (e.g., roadmaps, questions) cause public endpoints like /api/roadmaps/frontend to return 404. Deploy an automated idempotent migration script (scripts/seed-roadmaps.js) executed automatically during initial deployment.
Frontend Styling Assets High index.html imports Tailwind CSS via CDN script (https://cdn.tailwindcss.com). Triggers production console warnings and slows First Contentful Paint (FCP). Install Tailwind CSS as a PostCSS plugin in Vite. Build static, purged utility CSS into the bundle.
Session Layer vs. Stateless JWT Medium express-session with MongoStore was required for Passport Google OAuth, incurring database handshake overhead on serverless cold starts. Transition Google OAuth flow to exchange OAuth codes directly for JWTs, completely decoupling serverless APIs from stateful session stores.
Rate Limiting Configuration Medium Global rate limiter in server.js restricts /api/ to 100 requests / 15 minutes. High-frequency proctoring telemetry risks triggering false 429 errors. Segment rate limits: strict limits on /api/auth/*, relaxed high-throughput allowances for /api/camera/* and proctoring telemetry.
Repository Clutter Low Backup files exist in the repository (e.g. Dashboard.backup.jsx, Learn.jsx.backup, check_exam.js). Purge legacy backup files; leverage Git version control history for tracking earlier iterations.

4. Actionable Production Blueprint (Phased Roadmap)

Phase 1: Immediate Stabilization & Reliability (Week 1)

  1. S3 / Cloudflare R2 Object Storage Adapter:

    Replace local disk chunking in recordingService.js and cameraRoutes.js with S3 presigned URL generation:

    POST /api/camera/get-upload-url Payload: { sessionId: "...", chunkIndex: 1, mimeType: "video/webm" } Response: { uploadUrl: "https://bucket.r2.cloudflarestorage.com/...", key: "..." }
  2. Database Seeder Execution:

    Execute seeder scripts for the roadmaps and questions collections to populate foundational engineering tracks and prevent 404 responses on public routes.

  3. Vite PostCSS Tailwind Integration:

    Remove <script src="https://cdn.tailwindcss.com"> from app/frontend/index.html. Configure tailwind.config.js and postcss.config.js inside app/frontend for zero-runtime CSS overhead.

Phase 2: Architectural Optimization & Hardening (Week 2-3)

  1. Stateless Authentication Refactor:

    Refactor passport-google-oauth20 to execute in session: false mode. Upon Google callback, issue access and refresh JWTs directly, eliminating connect-mongo and cold-start session lookups.

  2. Database Index Optimization:

    Add compound indexes to MongoDB schemas to guarantee sub-10ms query execution:

    • users: { email: 1 }, { learnerId: 1 }, { googleId: 1 }
    • exam_sessions: { examId: 1, studentId: 1, status: 1 }
    • camera_recordings: { sessionId: 1, status: 1 }
    • roadmaps: { roadmapId: 1 }
  3. Differentiated Rate Limiting:

    Apply dedicated rate-limiters: Auth endpoints (10 req/min), general API (120 req/min), and proctoring telemetry (600 req/min).

Phase 3: Enterprise Readiness & Observability (Week 4+)

  1. Observability & Monitoring: Integrate Sentry for full-stack error tracking and Datadog/Axiom for serverless log aggregation.
  2. Client Error Boundaries: Wrap critical views (AdaptiveExamSession, Roadmap, CameraMonitor) in React Error Boundaries to prevent full-screen crashes during unexpected network hiccups.
  3. Automated CI/CD Pipeline: Establish GitHub Actions workflows to run unit tests, schema validation, and Cypress/Playwright integration tests on pull requests.
